# Hidden-style edge scenarios (plan section 8.2)

Inputs: `H*.json`, one scenario per file (H25 is an array, H26a-c are deliberately broken files, H29/H30 are perturbation pairs).
Expectations: `expectations.jsonl`, one JSON object per line, one line per plan ID (H01-H36). It is `.jsonl` so that `run`/`validate` on this directory never mistake it for a scenario. Expectations come from plan section 8.2, not from engine output.

Keys (all optional except `id`, `files`, `intent`):
- `files`: input files for this ID (H26 covers a, b, c; H29/H30 cover all their files).
- `status`: list of acceptable output statuses. `stack`: `"null"` or `"present"`.
- `style` / `style_not`: acceptable / forbidden `architecture_style` values.
- `layers`: `{layer: [names]}`; chosen component of that layer must contain any one name (case-insensitive substring of `choice`; `"None"` means choice starts with None). `layers_present` / `layers_absent`: supporting layers that must / must not appear.
- `forbidden_choices`: substrings that must not occur in any component `choice`.
- `required_warnings`: `{code, severity?, count?, min_count?, min_critical?}`; `required_warnings_any`: at least one of the list; `severity` is the minimum-required exact severity.
- `assumption_prefixes`: assumptions that must start with each string. `cost`: e.g. `{"min_gt": 0}`.
- `validation_errors`: `{count, fields}` (field paths, `$` for file-level). `validate_expect`: `valid`, `invalid` or `mixed` for `python3 -m stacksense validate`. `exit_code`: CLI exit code.
- `nearest_feasible_mentions`: strings that must appear in `nearest_feasible`.
- `output_count`, `output_statuses`: for array inputs (H25).
- `compare` / `per_file[file]`: perturbation checks against `base` (`public/Pn` = `scenarios/public/Pn.json`, otherwise a file in this folder). `may_change` / `must_change` list core layers; any core layer outside `may_change` must be identical (locality). `supporting_may_change` / `supporting_must_change` / `supporting_absent` likewise for supporting layers. Also `required_warnings`, `warning_disappears`, `cost` (`rises`/`drops`), `style`. `base_only_files` are baselines for a pair and are only checked for `status`.
- `manual`: assertions in prose from section 8.2 that need bespoke test code (cannot be expressed with the keys above).
- The 6 MB file of H26 is generated by the test at run time (not stored, to keep the repo small).
